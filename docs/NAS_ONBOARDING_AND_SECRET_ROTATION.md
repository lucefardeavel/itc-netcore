# NAS onboarding and secret rotation (Architecture Lock gates N6 / N7, AD-18)

Scope: ONE ISP instance (Option A); every step uses only that instance's database, FreeRADIUS and NAS.

## 1. Secret boundary (N6, AD-18)

RADIUS shared secrets must be recoverable: RADIUS signs and checks packets with them. They therefore cannot be hashed. The boundary decides who can read them:

| Secret | Stored | Readable by | Never |
|---|---|---|---|
| NAS shared secret (`nas.secret`) | RADIUS database | FreeRADIUS account (SELECT on `nas`), application account (CoA client, NAS admin) | rendered in the UI (NAS edit shows an empty field), logged (ErrorReporter redacts it), put on a command line (native CoA client, no `radclient`), written to audit / evidence |
| Router API password (`tbl_routers.password`, legacy devices only) | application database | application account | rendered (write-only field), logged (redacted) |
| `$db_pass`, `$app_secret`, `$api_secret`, `$radius_rest_secret` | `config.php` (mode 0640, owner the PHP user) | the PHP runtime | logged (redacted), used as each other's value (AppKey / ApiToken refuse equal secrets) |
| SNMP communities (session guard) | FreeRADIUS credential file (mode 0600, owner `freerad`) | FreeRADIUS guard program | in argv or logs (the guard reads the file) |

Least-privilege accounts are generated by `php system/reseller/grants.php`:
- No other database account may read `nas`.
- Backups that contain the database are secret material. Encrypt them at rest and restrict them to the instance operators (WP10 restore runbook).

## 2. Onboarding a NAS (N7)

1. Agree the NAS identity contract:
   - `nas.nasname` = the RouterOS `/radius src-address` = `NAS-IP-Address` of its accounting (WP8 OD-W8-4);
   - no NAT between the NAS and FreeRADIUS.
2. Generate a secret on the operator workstation, never in a shared chat or ticket. Use 32 or more random characters, not reused across NAS or instances:

   ```bash
   openssl rand -hex 24
   ```

3. In the application (Admin → RADIUS → NAS → Add):
   - name;
   - address (= `nasname`);
   - CoA port: `3799`;
   - the secret;
   - **Type `mikrotik_snmp`**. With any other type (default `other`) the session guard cannot verify the NAS: the release preflight `nas.verification` FAILs, and subscribers stay locked out after a lost Stop (`install/freeradius/README.md`, PF-0 / TD-2).
   - Add the NAS's SNMP read-only community to the guard credential file `${confdir}/nuxr/nas_snmp` (mode 0600 or 0400, owner `freerad`; procedure in `install/freeradius/README.md` "Credential file"). Then `sudo -u freerad ${confdir}/nuxr/nuxr_guard_selfcheck` must print `guard_selfcheck=OK` for it.
4. On RouterOS:
   - `/radius add address=<FreeRADIUS IP> secret=<secret> src-address=<nasname> service=ppp,hotspot timeout=3s require-message-auth=yes-for-request-resp`;
   - `/radius incoming set accept=yes port=3799`;
   - firewall: accept UDP 3799 only from the application host, then drop UDP 3799 from every other source
     (`/ip firewall filter add chain=input protocol=udp dst-port=3799 src-address=<application host> action=accept`, then the same
     rule without `src-address` and with `action=drop` right after it). RouterOS accepts a CoA only from the `address` of one of
     its `/radius` entries and ignores other sources: either the application host is the FreeRADIUS address of the `/radius` entry,
     or add a second `/radius` entry for the application host's address with the same secret;
   - PPP AAA accounting with interim updates. The application sends `Acct-Interim-Interval` in every Access-Accept and RouterOS
     uses it instead of the PPP AAA interim (PPP); for Hotspot the profile must say `radius-interim-update=received`, otherwise
     a fixed profile value wins. The quota interim is then set by the plan, not by the NAS;
   - NTP: `/system ntp client set enabled=yes servers=<ntp1>,<ntp2>` (two internal servers by IP) and a known time zone. The clock
     must stay within 10 s of the application (hard limit, typically under 2 s); `php system/reseller/health.php` warns when a NAS is more than 5 s AHEAD (a clock
     behind is not visible to it: monitor NTP on the NAS).
5. Restart FreeRADIUS. It reads the `nas` clients at start (`read_clients = yes`).
6. Verify:
   - one test login (Access-Accept);
   - accounting Start (radacct row with `nasipaddress = nasname`);
   - one Disconnect from the application (CoA ACK).
7. Run `php system/reseller/preflight.php` and confirm it passes.

## 3. Rotating a NAS secret (N7)

The NAS and FreeRADIUS must change together. During the change, requests signed with the old secret are dropped (authentication retries), so rotate in a maintenance window per NAS.

1. Generate the new secret (as above).
2. In the application, edit the NAS and set the new secret. The field is write-only; empty keeps the old one.
3. Restart or reload FreeRADIUS (clients are read at start).
4. Immediately set the same secret on RouterOS: `/radius set [find address=<FreeRADIUS IP>] secret=<new>`.
5. Verify a login, accounting and one CoA as in onboarding step 6.
6. Record the rotation (date, NAS, operator) in the operations log. Never record the secret.
7. Rotation interval: at least yearly, and immediately after:
   - staff turnover;
   - a suspected leak;
   - a backup exposure.

## 4. Rotating the application secrets

| Secret | Effect of rotation | Procedure |
|---|---|---|
| `$app_secret` | every staff and customer session, remember cookie, login link and public invoice link becomes invalid (users log in again) | set the new value in `config.php` (32+ random characters); no restart needed |
| `$api_secret` | every API token becomes invalid (staff log in through the API again) | set the new value in `config.php` |
| `$db_pass` | database login | change the database account password, then `config.php`; independent of every other secret since NEW-7 |
| `$radius_rest_secret` | only with the (disabled by default) rlm_rest device | change FreeRADIUS `rest` module and `config.php` together |

## 5. Removing a NAS

1. Disconnect or let its sessions end.
2. Remove it from RouterOS.
3. Delete the NAS row in the application.
4. Restart FreeRADIUS.

Its accounting history stays in `radacct`; it is never deleted.
