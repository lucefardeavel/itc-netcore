# حول هذا الدليل

يغطي هذا الدليل دورة حياة المشترك في ITC NetCore V1.0: إنشاء المشترك، وإسناد الباقة وتفعيلها، والدخول إلى البوابة، والقسائم. وهو موجّه إلى المديرين (Admin) والموزّعين (Agents) ومندوبي المبيعات (Sales) وفريق الدعم. المصادر: `docs/WP2_PERMISSION_MODEL.md` §6، و`docs/WP5A_ACTIVATION_MODEL.md`، و`docs/WP5B_LEGACY_CLOSURE_MODEL.md`، و`docs/OPERATOR_RECOVERY_RUNBOOK.md` §2، و`install/freeradius/README.md`، والمتحكّمات والقوالب المذكورة في `OPS_DOCS_SOURCES.md`.

> [!WARNING]
> إصدار مرشّح، لم يُقبل بعد للإنتاج. جرى التحقق من سلوك الشبكة في مختبر معزول على RouterOS CHR 7.24.5 فقط؛ ولم يُختبر طراز NAS المستهدف (TA-03 / TA-04 لم يُنفَّذا).

# 1. نوعان من المشتركين

| | مشترك مباشر (بلا موزّع) | مشترك تابع لموزّع |
|---|---|---|
| حقل المالك | فارغ (`manager_id` NULL) | وكيل (Agent) |
| من ينشئه | SuperAdmin / Admin | Admin (مع اختيار الوكيل المالك)، أو الوكيل نفسه، أو مندوب تابع لذلك الوكيل |
| إسناد الباقات عبر | أدوات الخدمة القديمة: الشحن (Recharge)، والتعبئة بقسيمة، والتمديد (Admin)، أو البوابة | شاشة **التفعيل** فقط (NEW / RENEW / REACTIVATE / CHANGE_PLAN) |
| من يدفع | المشترك (البوابة، الرصيد، القسيمة) أو شحن مجاني من Admin | محفظة الوكيل المالك، أياً كان من بدأ التفعيل |
| الخدمة الذاتية في البوابة (شحن، شراء، قسيمة، تمديد، إيقاف، تحويل رصيد) | متاحة بحسب الإعدادات | **مرفوضة** مع الرسالة: «This service is managed by your reseller and cannot be changed here. Please contact your authorized reseller.» |

# 2. إنشاء مشترك

**المكان:** Subscribers > Add subscriber (أو زر **+** للإجراءات السريعة على الهاتف).

| مجموعة الحقول | الحقول | ملاحظات |
|---|---|---|
| الهوية | اسم المستخدم، والاسم الكامل، وكلمة المرور، والهاتف، والبريد، وحقول العنوان، والإحداثيات | اسم المستخدم هو اسم دخول RADIUS (لخدمة Hotspot). يجب ألا يتعارض مع هوية RADIUS لمشترك آخر |
| الخدمة | نوع الحساب ونوع الخدمة | Hotspot أو PPPoE لتفعيلات الموزّعين |
| PPPoE | اسم مستخدم PPPoE وكلمة مروره وعنوان IP ثابت اختياري | المشترك الذي لديه خدمتا Hotspot وPPPoE معاً يحتاج **اسم مستخدم PPPoE مختلفاً**؛ فنوع الخدمة الثاني على مفتاح RADIUS نفسه مرفوض. ويجب أن يكون عنوان IP الثابت عنوان IPv4 صالحاً غير محجوز، و**فريداً بين جميع المشتركين** (لكل الأدوار)؛ واتركه فارغاً ليأخذ المشترك عنواناً من مجمّع NAS |
| الملكية | المالك (Admin فقط)، ومندوب المبيعات (اختياري) | للوكيل يكون المالك دائماً هو نفسه؛ وللمندوب يكون المالك وكيلَه ويُسند المشترك إليه. تُتجاهل حقول المالك المرسلة من الوكلاء والمندوبين |
| الإشعار | إرسال رسالة ترحيب (قنوات SMS / WhatsApp / البريد بحسب الإعداد) | اختياري |

**من يحق له الإنشاء:**

| الفاعل | يُضبط المالك على | الإسناد لمندوب |
|---|---|---|
| SuperAdmin / Admin | فارغ (مشترك مباشر، الافتراضي) أو وكيل نشط مسجَّل | اختياري؛ ولمندوب تابع لذلك المالك فقط |
| Agent | نفسه | اختياري؛ ويجب أن يكون مندوباً **مباشراً** نشطاً ومسجَّلاً |
| Sales | وكيله الأب | نفسه |
| Report والحسابات غير الموضوعة أو المجمَّدة | مرفوض | — |

> [!NOTE]
> يُرفض الإنشاء إذا تعارضت الهوية الجديدة مع هوية قائمة في أي مكان من النسخة (مثل `username` يساوي `pppoe_username` لمشترك آخر، أو عنوان IP ثابت مُسنَد إلى مشترك آخر). ويتلقى الوكلاء والمندوبون **رسالة رفض عامة واحدة** لا تذكر القيمة المستخدمة ولا صاحبها، أما المديرون فيرون السبب المحدد. اختر قيمة أخرى. وفي التثبيت الجديد لا توجد بيانات قديمة، فلا يمكن إلا ظهور تعارضات جديدة.

بعد الإنشاء، تعديلات سجل المشترك (كلمة المرور، وهوية PPPoE، والحالة، والمزامنة) من عمل **Admin**؛ فلا يستطيع الوكلاء والمندوبون تعديل المشتركين أو إيقافهم أو حذفهم أو مزامنتهم.

# 3. إسناد الباقة وتفعيلها (مشتركو الموزّعين)

**المكان:** عرض المشترك > *Renew / Change plan*، أو Subscribers > Activations > Activate / Renew.

1. اختر الباقة. لا تظهر إلا الباقات المعروضة على الموزّع البائع: مسعّرة، ومتاحة، ومفعّلة، على جهاز **Radius**، ومن نوع Hotspot أو PPPOE.
2. اضغط **Review**. يستنتج الخادم الإجراء من الخدمة الحالية للمشترك:

   | الخدمة الحالية | الإجراء | الفترة الجديدة |
   |---|---|---|
   | لا شيء | NEW | تبدأ الآن |
   | الباقة نفسها وما زالت نشطة | RENEW | تمتد من تاريخ الانتهاء الحالي |
   | الباقة نفسها منتهية أو متوقفة | REACTIVATE | تبدأ الآن |
   | باقة أخرى | CHANGE_PLAN | تبدأ الآن (بلا تناسب زمني) |

3. راجع المعاينة: سعر الجملة (يُخصم من محفظة الوكيل المالك)، وسعر البيع، والرصيد المتاح الآن وبعد العملية، والفترة الجديدة.
4. تغيير الباقة الذي يستبدل وقتاً مدفوعاً يطلب إقراراً صريحاً بأن الوقت المدفوع المتبقي سيضيع.
5. **التأكيد.** تُحجز الأموال، وتُجهَّز الخدمة على RADIUS ويُتحقق منها، ثم تُسوّى (خصم واحد). تعرض صفحة النتيجة الخط الزمني للمراحل ورقم الفاتورة.

> [!FINANCE-WARNING]
> عند عدم كفاية الرصيد المتاح يبقى زر التأكيد معطّلاً، ويرفض الخادم أي إرسال قسري. وإذا كانت نتيجة الشبكة غير واضحة، يظهر التفعيل بوصفه بحاجة إلى متابعة، و**لا يُحرَّر المبلغ المحجوز تلقائياً أبداً**، ولا يُخصم شيء مرتين. ويعالجه Admin (`incident_troubleshooting_guide`).

**حالات الرفض الشائعة**

| الرسالة / الرمز | المعنى | ما العمل |
|---|---|---|
| `ACTIVATION_IN_PROGRESS` | لدى المشترك تفعيل لم يكتمل | انتظر؛ وإن استمر، يعالجه Admin بعد 5 دقائق |
| `CONCURRENCY_RETRY` («please try again») | نشاط متزامن كثيف على محفظة واحدة (MariaDB). قد تبقى الأموال **محجوزة** دون خصم أو منح خدمة | لا تكرّر المحاولة مراراً. اطلب من Admin استئناف التفعيل المعلّق أو إلغاءه بعد مرور 5 دقائق عليه |
| رصيد غير كافٍ | الرصيد المتاح أقل من سعر الجملة | يموّل الموزّعَ أبوه أو المزوّد |

**التجديد.** لا يوجد في V1 تجديد تلقائي لمشتركي الموزّعين. عند انتهاء الفترة تفرض مهمة cron الانتهاء، ويجدّد الموزّع عبر شاشة التفعيل.

**الإنهاء المبكر.** لا تنتهي خدمة مشترك الموزّع إلا بانتهاء المدة أو بـ**عكس** Admin للتفعيل المكتمل (مع ذكر السبب). أما الإيقاف و«حذف الباقة النشطة» فمرفوضان لهؤلاء المشتركين.

# 4. إسناد الباقات للمشتركين المباشرين (Admin)

| المهمة | القائمة | ملاحظات |
|---|---|---|
| شحن باقة | Services > Recharge Customer («إعادة شحن اشتراك العميل») | الشحن المجاني يتطلب الصلاحية `service.recharge_free`؛ والدفع من الرصيد يمرّ عبر خدمة الرصيد |
| تعبئة بقسيمة | Services > Refill Customer («شحن العميل بقسيمة») | استرداد ذرّي واحد، مرة واحدة بالضبط |
| تعبئة الرصيد | Services > Refill Balance | فقط عند تفعيل الرصيد في الإعدادات |
| التمديد وتعديل الباقة والإيقاف | عرض المشترك / Active Customers | مُدقَّقة |

# 5. باقات حصص البيانات والوقت

- تحمل الباقة **المحدودة** (Limited) حصة بيانات (ميغابايت أو غيغابايت كاملة بالنظام العشري: 1 GB = 10^9 بايت، تنزيلاً ورفعاً لكل فترة فوترة)، أو حصة وقت (دقائق أو ساعات)، أو كلتيهما.
- تُفرض الحصة بحدود الراوتر نفسه إضافة إلى منفّذ المحاسبة (`quota.php enforce` كل دقيقة). **وهي محدودة التجاوز لكنها غير دقيقة بالبايت، ولا يجوز بيعها أبداً بوصفها سقفاً دقيقاً بالبايت.** والاستخدام الزائد على الحصة لا يُحتسب على المشترك ولا يُرحَّل إلى الفترة التالية.
- يُرفض دخول المشترك الذي استنفد حصته بالرسالة «Data quota exhausted or unavailable».
- يستطيع الدعم قراءة استخدام المشترك للفترة: `php system/reseller/quota.php usage <USERNAME>` (الفعلي، والقابل للفوترة، والتجاوز؛ قراءة فقط).

# 6. فحص أول اتصال

1. يتصل المشترك (طلب PPPoE أو دخول Hotspot) ببيانات اعتماد RADIUS.
2. يتحقق الموظفون من عرض المشترك (الخدمة نشطة وتاريخ الانتهاء)، ولخدمة PPPoE من وجود مجمّع عناوين IP الخاص بالباقة على NAS (غياب المجمّع يعطي Access-Accept دون عنوان IPv4).
3. إذا فشل الدخول، انظر `incident_troubleshooting_guide` (قسما «RADIUS reject» و«Customer cannot reconnect»).

# 7. الدخول إلى بوابة المشترك

| الموضوع | السلوك |
|---|---|
| الدخول | اسم المستخدم وكلمة المرور في صفحة دخول البوابة (تعرض اسم الشركة وإعلان الدخول) |
| التسجيل الذاتي | متاح ما لم يُعطَّل في الإعدادات (`disable_registration`)، مع تحقق اختياري برمز SMS |
| نسيان كلمة المرور / اسم المستخدم | رمز تحقق إلى الهاتف أو البريد |
| الدخول بقسيمة | تقبل صفحة الدخول رمز القسيمة؛ ويُرفض إذا تعارض اسم القسيمة مع مشترك تابع لموزّع |
| الحالة | المشترك المحظور (Banned) لا يستطيع دخول البوابة |
| الصفحة الرئيسية | معلومات الحساب والباقة الحالية وتاريخ الانتهاء، والعناصر المفعّلة في Settings > Widgets |
| زر المزامنة (Sync) | يعيد إرسال الحساب إلى الشبكة (إعادة تجهيز محدودة؛ لا يمنح خدمة أبداً) |
| تغيير كلمة المرور | متاح للنوعين؛ ويعيد تجهيز حساب الشبكة |
| شراء باقة إلكترونياً | للمشتركين المباشرين فقط، وفقط إذا ثبّت SuperAdmin إضافة بوابة دفع وأعدّها. **لا تأتي أي بوابة دفع مع V1.0** |
| إيقاف باقة مسبقة الدفع (المشتركون المباشرون) | تنصّ رسالة التأكيد على أن الوقت المدفوع المتبقي يضيع ولا يُسترد |

# 8. القسائم

| الخطوة | من | الإجراء |
|---|---|---|
| التوليد | SuperAdmin / Admin فقط | Services > Vouchers > Add vouchers: النوع، والراوتر **Radius**، والباقة، وعدد القسائم، وصيغة الرمز، والبادئة، وطول الرمز؛ مع طباعة اختيارية |
| التوزيع | المزوّد | الرموز مقنّعة في القوائم والتقارير؛ تعامل مع الرموز المطبوعة كالنقد |
| الاسترداد | المشترك المباشر | صندوق القسيمة في البوابة، أو الدخول بقسيمة، أو Services > Refill Customer من Admin |
| الاسترداد لمشترك تابع لموزّع | — | **مرفوض.** مشتركو الموزّعين يفعّلهم موزّعهم |
| العرض | الوكلاء | القسائم المولَّدة داخل شجرتهم (قراءة فقط) |
| المراجعة | المشغّل | القسيمة التي لم يثبت منحها تبقى `CLAIMED` ولا تعود قابلة للاسترداد حتى يقرّر المشغّل (`reconcile.php voucher-review`، دليل الاسترداد §2). لا تُعِد إصدار قسيمة دون تحقق أبداً |

# 9. قائمة فحص للمشترك الجديد

- [ ] إنشاء المشترك بالمالك الصحيح (مباشر أو وكيل)، وبمندوب المبيعات إن وُجد
- [ ] اسم مستخدم PPPoE مختلف إذا كان للمشترك نوعا الخدمة
- [ ] تفعيل الباقة (مشترك موزّع) أو شحنها / تعبئتها (مشترك مباشر)، مع تدوين رقم الفاتورة
- [ ] نجاح أول دخول وظهور المحاسبة
- [ ] اختبار دخول البوابة، وإبلاغ المشترك بطريقة التواصل مع موزّعه أو مع المزوّد
